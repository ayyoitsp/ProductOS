# The parse foil — refused before it loads

⛔ **A separate corpus, not a separate file, and the reason is a real constraint.**

`check` stops after a parse failure and reports nothing derived, because one unloaded file
makes every other finding an artefact: a stray `retention: two years` on a slot produced three
`rule-governs-nothing` refusals advising *"widen the selector, **or delete it**"* against
*"Only a parent may change what a kid has"* — the rule governed nothing because the file
declaring the exchanges it governs had not loaded. An author told to iterate until the gate is
green deletes the authorization rule from a children's money product.

So schema-level attacks cannot share a corpus with semantic ones: the early return would mask
every detector `v2-foil/` exists to exercise. This corpus holds the attacks that must be
refused by the schema itself; `v2-foil/` holds the ones that must be refused by `check`.
